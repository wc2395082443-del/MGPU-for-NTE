# 并行流水线与低延迟版 preview.3

发布日期：2026-11-09。采用用户逐阶段确认正常的主模块 `8ADEAA05`＋helper `446FD260`，对应此前保存的双 Pass 异步版本及三阶段测量清理。

4080 SUPER 负责游戏渲染、游戏 DLSS 超分，关闭游戏进程的源端 FG；5080 负责 NR 和其后的 NVIDIA 官方 DLSS 多帧生成，仍可请求六倍。官方 SDK 负责生成与呈现节拍，helper 负责数据、资源和输出窗口。

## 本次更新

| 改动 | 解决的问题与处理方式 |
| --- | --- |
| 更新游戏构建识别 | 对新版异环重新定位并校验 ForceTagging 只读绑定，继续保护源端 `slDLSSGSetOptions` 的 Off 转发，保留引导和原生 Reflex 调用。 |
| 拍照／菜单后的 FG 恢复 | 源标记暂时缺失时保留 helper 生命周期，后续有效源帧恢复后继续输出；启动历史过期也有有界处理。 |
| 清理过期覆盖画面 | 无新鲜完成结果时隐藏旧输出，有新结果后恢复，处理场景切换时旧画面盖住仍在运行的原生游戏。 |
| 输入环槽回收 | 优先复用已退休槽，保护完整待处理 tuple，安全回收真正失效的旧项，避免输入身份和资源生命周期错位。 |
| NR 较慢时的并行背压 | 保留三个在途额度。只有额度耗尽才等最老任务释放容量，使源速率随慢端收敛；跨帧渲染、COPY、NR 仍可并行。连续源帧丢弃和由此触发的 gap reset 得到抑制。 |
| 提前等待，降低输入延迟 | 将容量等待放到原生 Reflex Sleep 之前，保留提交后的安全保护，让等待尽量发生在新一轮输入／模拟之前。 |
| 双 Pass 异步 | 官方输出模式下两遍 NR 也可进入已有三槽异步路径，保留两次评估、原有 barrier、参数和引导。 |
| 三阶段清理测量 | 先关闭 GPU 计时和纯 NR 诊断像素采样，再关闭主模块详细 CPU／队列采集与纯统计，最后关闭 helper 可选追踪和纯速率统计。 |

NR 快于游戏渲染时，容量足够就继续提交。NR 慢于游戏渲染时，通过有界在途额度限制超前量；无需每张渲染帧都等待自己的 NR 完成。正常历史失效、资源重建等仍保留必要 reset。

## 测量清理的具体范围

- GPU timestamp／校准查询与纯 NR 诊断像素样本关闭。
- 主模块详细 CPU 采集、队列观察包装、锁耗时累计和游戏 Present FPS 统计关闭；真实锁、队列提交和 Wait／Signal 保留。
- helper 编译启用 `MGPU_HELPER_NO_TRACE=1`：不分配追踪帧数组，不创建采集事件、追踪写入线程或 CSV／二进制输出，阶段 mark 不读统计时钟，source age 和纯速率统计停止更新。
- `MetaProbe`、`PresentAudit`、`PanelStats`、部分资源发现与状态计数、常规健康／错误日志及旧条件分支的读回仍保留。输入启动、帧身份、Reflex／PCL、资源 fence、heartbeat、超时和输出存活保护使用的状态仍有效。

因此面板内部分速率／诊断字段可能不再更新，不能据此判断官方 FG 是否停止。外部 RTSS 可继续只监控 helper。大规模时间线采集需要单独的诊断构建。

## 验证与性能记录

用户确认登录界面与双 Pass 均不再闪烁，提前等待版延迟低，双 Pass 异步版体验良好；三阶段测量清理逐一安装后均确认正常，最后 helper 阶段反馈“没问题”。这是用户实机反馈，尚无本版新的输入到光子延迟数值或同场景 FPS 对照。

源快照的相关回归为 14 项主测试＋11 项 helper 测试，覆盖源 FG 保护、三额度及串行负例、提前背压、双 Pass 资格、测量关闭后的锁／启动／存活契约。发布时另做源码构建、安装／回退和包校验；结果见 [构建验证](BUILD.md)。

README 中的基础帧 28→34（约 21.4%）、单卡 5080 超级性能＋六倍约 120 FPS、双卡质量＋六倍 160 FPS 以上，保留其历史条件与来源。本次更新没有新增同条件性能采样。
