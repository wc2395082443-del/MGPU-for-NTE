# 性能证据与口径

当前preview.2采用4080S源FG Off、5080 NR后官方FG最多六倍的分工。前台源SDK Off、标签/NR/helper输出已有记录；新GPU图的helper可见状态为0、每源帧SDK1，因此58.17%的COPY/DIRECT查询交集尚不能证明前台六倍性能收益。最新测量条件见[源端FG关闭版](SOURCE-FG-OFF.zh-CN.md)，以下28→34及160+仍为各自历史条件的记录。

测试主角色：4080 SUPER渲染游戏，RTX 5080运行NR。历史COPY记录使用4K颜色、2562×1441引导、单次NR、强度/结构/肤色/色调2、风格1、AutoMask及游戏DLSS Quality。各日期的场景和负载分别记录。

## 帧生成、手感与当前限制

### 第二张卡承担六倍FG时的基础帧观察

六倍采用NVIDIA官方DLSS帧生成，由Streamline／DLSS-G运行在5080上；用户最新反馈画面效果非常好。

历史M343关闭FG时记录33.020313个NR帧/s；M351六倍请求时真实源33.05/s、SDK194.85/s；M352为33.1真实帧/s、SDK195.2/s。**这些窗口的基础帧基本持平，六倍主要利用副卡算力增加输出。** 5080同时承担NR与FG，COPY、资源退休、SDK节拍和Reflex反馈也会影响源周期。详见[helper功能说明](HELPER.zh-CN.md)。

## 稳定性

R333曾混用engine-frame与accepted-seal槽位，跳帧后失配，所查26个传输样本均出现错位。后续统一身份，并保留自有快照和退休保护。M340/M341/M342实测后，用户确认画面稳定。

M362的输入解耦明显改善了用户报告的转动顿挫；M363随后补齐分层窗口穿透，处理按钮、滚轮和光标问题。

M366曾获更流畅反馈但无明显基础帧增益，之后收到启动异常并回退；没有可用栈证明该改动是根因。M367从未部署。两者不在首发包内。
